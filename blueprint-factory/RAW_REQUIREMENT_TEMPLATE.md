## กติกาสำหรับผู้เก็บ Requirement
1. เขียนตามที่โรงพยาบาลบอก ไม่ต้องทำให้ดูสมบูรณ์.
2. ถ้าไม่รู้ ให้เขียน `ไม่ทราบ / ยังไม่ได้ถาม`.
3. ไม่ต้องเติม workflow จากประสบการณ์ตัวเอง.
4. ไม่ต้องหา JCI / HA / ISO clause เอง.
5. ไม่ต้องรอให้ทุกคำถามมีคำตอบก่อนส่งให้ Blueprint Analyst.
6. แนบตัวอย่างจริงเมื่อโรงพยาบาลมีให้.

## สิ่งที่ Blueprint Analyst จะทำต่อ
`Raw Requirement → Hospital Truth → Hospital System Analysis → Standards/Compliance Review → Working Assumptions/TBD → Application Blueprint → Quality Gate`

ถ้าข้อมูลเพียงพอสำหรับ mockup discovery โดยไม่สร้างความเสี่ยง Blueprint จะเป็น `PROTOTYPE READY` และทีมสามารถสร้าง Mockup ไปใช้ Confirm Requirement กับโรงพยาบาลได้.
