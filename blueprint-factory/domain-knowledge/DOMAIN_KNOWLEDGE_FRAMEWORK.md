# Gorilla HIS — Domain Knowledge Framework v1.0

## Principle
Factory quality must come from versioned, evidence-backed domain knowledge, not from a long prompt or AI memory.

Analysis sequence:

`Domain Knowledge Pack → Domain Standard Flow → Universal Workflow Challenge → Hospital Requirement Delta → Applicable Standards Overlay → Expert Challenge → Blueprint → Scenario Simulation → UI Factory`

A Domain Knowledge Pack is reference knowledge. It is never Hospital Confirmed merely because it exists in Git.

## Required Pack Structure
For each material HIS domain create, as applicable:
- `DOMAIN_OVERVIEW.md`
- `STANDARD_WORKFLOW.md`
- `ROLE_MATRIX.md`
- `SCENARIO_CATALOG.md`
- `DATA_SOURCE_OF_TRUTH.md`
- `INTEGRATION_MAP.md`
- `FINANCE_IMPACT.md`
- `PRIVACY_SECURITY.md`
- `STANDARD_MAPPING.md`
- `EXPERT_CHALLENGE_CHECKLIST.md`

A compact combined file is allowed for early maturity if it covers all applicable headings and source evidence.

## Knowledge Source Priority
1. Hospital/project primary evidence for local truth.
2. Official regulator/law/standards owner/accreditor.
3. Official national/professional/domain authority guidance.
4. Established HIS/hospital practice as recommendation.
5. Expert reasoning as advisory only.

Do not use AI memory, blogs, vendor marketing, social posts or search snippets as authoritative proof.

## Missing Pack Rule
If an activated material domain has no adequate Domain Knowledge Pack:
1. do not pretend the Factory has complete domain knowledge;
2. build a temporary source-backed `DOMAIN RESEARCH CANDIDATE` from authoritative sources;
3. record source/version/applicability/verification;
4. run Universal Workflow Challenge;
5. expose unresolved domain decisions;
6. only after evidence review may the candidate be promoted into repository domain knowledge.

For high-risk clinical/legal domains, absence of an adequate pack prevents `READY FOR DEV HANDOFF`. A safe Discovery Prototype may proceed only when unknown effects are contained and clearly classified.

## Pack Quality Gate
PASS requires:
- material scenario branches identified;
- roles/handoffs covered;
- identity/encounter/source-of-truth covered;
- core workflow and exceptions covered;
- downstream transactions/integrations covered;
- finance impact considered;
- privacy/security considered;
- authoritative standards/domain sources recorded where relevant;
- Expert Challenge Checklist present;
- no local hospital rule invented.

## Maintenance
When an authoritative edition, regulation, integration contract or hospital policy changes, update affected packs and regression-test affected domains.
