# Gorilla HIS — Authoritative Source Policy v1.0

Purpose: make standards/law/best-practice claims auditable without weakening the v3.2 Relevance Gate.

## Core Rule
Evidence Assurance runs **after relevance is established**. A source does not create scope by itself.

`NO RELEVANCE → NO GAP → NO STANDARD LOOKUP REQUIRED.`

A standard may strengthen or verify a relevant issue; it MUST NOT be used to manufacture a hospital requirement unrelated to the supplied module/workflow.

## Evidence Assurance Levels
- **A — HOSPITAL PRIMARY EVIDENCE**: explicit hospital requirement, policy, approved workflow, decision record, contract/TOR or hospital-confirmed source supplied for the project.
- **B — AUTHORITATIVE EXTERNAL SOURCE**: current official law/regulator/standards-owner/accreditor publication whose applicability has been verified.
- **C — AUTHORITATIVE GUIDANCE**: official guidance from regulator, standards owner, recognized national/professional authority; supports a principle but may not itself be mandatory.
- **D — ESTABLISHED HIS / HOSPITAL PRACTICE**: expert practice pattern; useful for recommendations, never proof of this hospital's requirement.
- **E — EXPERT REASONING ONLY**: analytical inference with no independent authoritative source; advisory only.

## Required Evidence Record
For every expert-created CRITICAL/HIGH item and every formal standards/legal claim record, where applicable:
- Evidence Assurance Level
- Source Owner
- Document / Source Title
- Edition / Version / Effective Date
- Section / Topic / Clause — only when exact text was verified
- Official Source Locator
- Verified Date
- Applicability to this module/hospital
- Claim Type: `HOSPITAL REQUIREMENT / FORMAL REQUIREMENT / AUTHORITATIVE GUIDANCE / BEST PRACTICE / EXPERT REASONING`
- Verification Status: `VERIFIED / PARTIALLY VERIFIED / NEEDS VERIFICATION / NOT APPLICABLE`

## Formal Claim Gate
Words such as `requires`, `shall`, `mandatory`, `must comply`, or an exact clause/section may be used for an external standard/law only when:
1. source is Level B;
2. official source is identified;
3. exact requirement/section is verified;
4. edition/effective date is known;
5. applicability to the current module/hospital is established.

Otherwise use `RECOMMENDATION — STANDARD VERIFICATION REQUIRED`, `AUTHORITATIVE GUIDANCE`, or `BEST PRACTICE` as appropriate.

## Source Quality Rules
Prefer, in order:
1. hospital/project primary evidence for Hospital Truth;
2. official regulator / law / standards owner / accreditor;
3. official professional/national authority guidance;
4. secondary literature only as supporting context;
5. expert reasoning.

Do not treat blogs, vendor marketing, search snippets, forums, AI memory, or secondary summaries as authoritative proof of a formal requirement.

## Freshness Rule
For standards/law claims verify current edition/status when practical. If current status cannot be verified, mark `NEEDS VERIFICATION`; do not silently rely on remembered editions.

## Conflict Rule
When Hospital Confirmed workflow conflicts with a verified external obligation or safety principle:
- preserve Hospital Truth as supplied;
- raise a separate CR/GAP with evidence;
- identify decision owner;
- do not silently rewrite the workflow.

## Copyright / Licensed Standards Rule
Do not copy licensed standards into the repository unless licensing permits it. Store metadata, official locator, verified topic/section and concise evidence notes instead.

## Non-Promotion Rule
Evidence strength never promotes an item to `HOSPITAL CONFIRMED`. Only explicit hospital/user confirmation can do that.
