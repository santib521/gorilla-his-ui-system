# Patterns — Index

Pattern = โครงหน้าจอระดับ **หน้าเต็ม** ที่ประกอบขึ้นจากหลาย component ใน `../components/` ต่อเข้าด้วยกัน
เอกสารเหล่านี้เป็น**คำอธิบาย + โครง wireframe แบบข้อความ** ไม่ใช่ไฟล์ HTML รันได้ (component ต่างหากที่เป็น HTML ใช้งานได้จริง)

ก่อนออกแบบหน้าจอใหม่ ให้เช็คว่ามี pattern ที่ตรงกับ feature ของคุณหรือไม่ — ถ้ามีให้ยึด pattern นั้นเป็นโครงหลัก

| Pattern | ใช้เมื่อไหร่ | ตัวอย่าง feature ที่ใช้ |
|---|---|---|
| `list-detail-page.md` | ต้องแสดงรายการทางซ้าย + รายละเอียดทางขวา | รายชื่อผู้ป่วยรอตรวจ + ประวัติ, รายการ Order ยา + รายละเอียด |
| `search-and-table.md` | ค้นหา/กรอง แล้วแสดงผลเป็นตาราง | ค้นหาผลแล็บ, ค้นหารายการยาในคลัง |
| `form-wizard.md` | กรอกข้อมูลหลายขั้นตอนต่อเนื่อง | ลงทะเบียนผู้ป่วยใหม่, รับยาผู้ป่วยใน |
| `order-entry.md` | สั่งบางอย่างเข้าระบบให้ module อื่นดำเนินการต่อ | สั่งตรวจ Lab, สั่งยา, สั่ง X-ray |
| `result-review.md` | ตรวจทานผลก่อนรับรอง/ส่งต่ออย่างเป็นทางการ | รับรองผล Lab, อ่านผล X-ray |
| `approval-confirmation.md` | ยืนยัน action ที่มีผลกระทบสำคัญ ก่อนดำเนินการจริง | ยกเลิกนัด, สั่งยาที่มีความเสี่ยง, รับรองผล critical |
| `error-handling.md` | ออกแบบ error/failure state ให้ครบทุกจุดที่อาจล้มเหลว | ทุก feature ที่มีการบันทึก/ดึงข้อมูล |
| `dashboard-home.md` | หน้าแรกของ module: stat card สรุปภาพรวม + worklist หลัก — พบจริงใน Visual Audit | หน้า Home/Dashboard ของทุก module |

## กฎการเพิ่ม pattern ใหม่

เหมือน component: ต้องผ่านที่ประชุม weekly design sync ก่อน ห้ามเพิ่มเองโดยไม่แจ้งทีม
