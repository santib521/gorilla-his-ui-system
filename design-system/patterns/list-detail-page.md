# Pattern: List–Detail Page

## ใช้เมื่อไหร่
ผู้ใช้ต้องเลือกรายการจากลิสต์ แล้วดูรายละเอียดของรายการนั้นในพื้นที่เดียวกันโดยไม่เปลี่ยนหน้า
เช่น: รายชื่อผู้ป่วยรอตรวจ (ซ้าย) + ประวัติ/ vitals ของผู้ป่วยที่เลือก (ขวา), รายการ Order ยา (ซ้าย) + รายละเอียด Order (ขวา)

## โครงหน้าจอ

```
┌─────────────────────────────────────────────────────────────┐
│  Top bar (โลโก้ / module switcher / user)                     │
├───────────────┬─────────────────────────────────────────────┤
│               │  [ patient-banner.html ] (ถ้ารายละเอียดคือผู้ป่วย)│
│  ซ้าย: List   │  [ alert-banner.html ]  (ถ้ามี critical)        │
│  (30–35%)     │                                                │
│               │  ขวา: Detail (65–70%)                          │
│  - search bar │  - เนื้อหารายละเอียด (form / table / tabs)      │
│  - list item  │                                                │
│    ×N         │                                                │
│               │                                                │
└───────────────┴─────────────────────────────────────────────┘
```

## Component ที่ใช้ประกอบ
- `patient-search-bar.html` — ช่องค้นหาด้านบนของ list ฝั่งซ้าย
- `status-badges.html` — แสดงสถานะแต่ละ item ใน list (เช่น รอตรวจ/แพ้ยา)
- `patient-banner.html` + `alert-banner.html` — หัวของฝั่ง detail เมื่อ detail คือข้อมูลผู้ป่วย
- `modal-dialog.html` — สำหรับ action ยืนยัน (เช่น ยกเลิกนัด) จาก list item

## กฎการใช้งาน
- List item ที่กำลังเลือกอยู่ต้องมี highlight ชัดเจน (พื้นหลัง `--color-blue-50` + border ซ้าย `--color-blue-500`)
- ถ้า list ว่าง (ไม่มีผลลัพธ์) ต้องมี Empty state ตาม `design-rules.md` § 8
- ฝั่งซ้ายต้อง scroll ได้อิสระจากฝั่งขวา (ไม่ scroll พร้อมกันทั้งหน้า)
- Responsive ไม่จำเป็นต้องรองรับ mobile แต่ต้อง fluid ได้ถึง 1920px (ดู `design-rules.md` § 2)
