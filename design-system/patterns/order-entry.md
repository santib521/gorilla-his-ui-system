# Pattern: Order Entry

## ใช้เมื่อไหร่
แพทย์/ผู้ใช้งานต้อง "สั่ง" บางอย่างเข้าสู่ระบบเพื่อให้อีก module หนึ่งดำเนินการต่อ
เช่น: แพทย์สั่งตรวจ Lab, สั่งยา (สำหรับ Pharmacy), สั่ง X-ray (สำหรับ Radiology)

## โครงหน้าจอ

```
┌─────────────────────────────────────────────────────────────┐
│  [ patient-banner.html ]                                      │
│  [ alert-banner.html ] (ถ้ามีแพ้ยา/ข้อห้ามที่เกี่ยวกับ order นี้)│
├─────────────────────────────────────────────────────────────┤
│  ค้นหารายการที่จะสั่ง (ยา/รายการตรวจ) [ search input ]         │
│  รายการที่เลือกแล้ว:                                          │
│    - รายการ 1  [จำนวน/ความถี่]  [ลบ]                          │
│    - รายการ 2  [จำนวน/ความถี่]  [ลบ]                          │
│  หมายเหตุ/Diagnosis code ที่เกี่ยวข้อง [ textarea ]             │
├─────────────────────────────────────────────────────────────┤
│                                   [ ยกเลิก ]  [ ยืนยัน Order ]  │
└─────────────────────────────────────────────────────────────┘
```

## Component ที่ใช้ประกอบ
- `patient-banner.html` + `alert-banner.html` — บริบทผู้ป่วยและคำเตือนต้องเห็นตลอด (ux-rules.md § 1)
- `patient-search-bar.html` — ปรับใช้เป็น "ค้นหารายการยา/รายการตรวจ" แทนค้นหาผู้ป่วย (โครง component เดียวกัน)
- `form-controls.html` — จำนวน/ความถี่/หมายเหตุ
- `modal-dialog.html` — ยืนยัน order ก่อนส่งจริง (ดู pattern `approval-confirmation.md`)

## กฎการใช้งาน
- ถ้ามีประวัติแพ้ยา/ข้อห้ามที่ตรงกับรายการที่กำลังสั่ง ต้อง**บล็อกการยืนยันแบบ hard-stop** ไม่ใช่แค่เตือนเฉย ๆ (ดู `modules/pharmacy/README.md`)
- แสดงรายการที่เลือกไว้ชัดเจนก่อนกดยืนยัน ป้องกันสั่งผิดรายการ/ผิดจำนวน
- Order ที่ส่งสำเร็จ ต้องมี `notification-toast.html` (Success) ยืนยันให้ผู้ใช้เห็นทันที
