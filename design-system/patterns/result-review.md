# Pattern: Result Review

## ใช้เมื่อไหร่
ผู้ใช้งาน (แพทย์/นักเทคนิคการแพทย์) ต้องตรวจทานผลลัพธ์ก่อนจะ "รับรอง/ส่งต่อ" อย่างเป็นทางการ
เช่น: นักเทคนิคการแพทย์ตรวจทานผล Lab ก่อนรายงาน, แพทย์ตรวจทานผล X-ray ก่อนวินิจฉัย

## โครงหน้าจอ
ใช้ pattern `list-detail-page.md` เป็นฐาน โดยฝั่ง detail เพิ่มพื้นที่ "การรับรองผล":

```
┌───────────────┬─────────────────────────────────────────────┐
│  Worklist      │  [ patient-banner.html ]                     │
│  (worklist.html)│  ผลลัพธ์ที่ต้องตรวจทาน (lab-result-table.html) │
│                │  ┌───────────────────────────────────────┐  │
│                │  │  ความเห็น/หมายเหตุผู้ตรวจทาน [ textarea ] │  │
│                │  └───────────────────────────────────────┘  │
│                │           [ ส่งกลับแก้ไข ]  [ รับรองผล ]      │
└───────────────┴─────────────────────────────────────────────┘
```

## Component ที่ใช้ประกอบ
- `worklist.html` — คิวผลที่รอตรวจทาน
- `lab-result-table.html` — แสดงผลพร้อม flag ผิดปกติ
- `patient-banner.html` — บริบทผู้ป่วย
- `modal-dialog.html` — ยืนยันก่อนรับรองผล (โดยเฉพาะถ้ามีค่า critical)

## กฎการใช้งาน
- ถ้าในผลมีค่า **critical** ต้องแสดง `alert-banner.html` เตือนก่อนให้กดรับรองได้ (ป้องกันมองข้าม)
- การรับรองผลถือเป็น action สำคัญ ต้องผ่าน `modal-dialog.html` ยืนยันซ้ำเสมอ (ดู pattern `approval-confirmation.md`)
- เก็บ mock state ว่า "รับรองแล้วโดยใคร เมื่อไหร่" แสดงไว้เพื่อความน่าเชื่อถือ แม้เป็นแค่ mockup
