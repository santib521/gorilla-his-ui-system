# Pattern: Search + Table

## ใช้เมื่อไหร่
ผู้ใช้ต้องค้นหา/กรองข้อมูลจำนวนมาก แล้วดูผลลัพธ์เป็นตารางที่สแกนสายตาได้เร็ว
เช่น: ผลแล็บของผู้ป่วย, รายการยาในคลัง, ประวัติการมาตรวจ

## โครงหน้าจอ

```
┌─────────────────────────────────────────────────────────────┐
│  Page title                                                  │
├─────────────────────────────────────────────────────────────┤
│  [ search input ]  [ filter dropdown ×N ]     [ ปุ่ม action ] │
├─────────────────────────────────────────────────────────────┤
│  ตาราง (sortable column header)                              │
│  แถวที่มี flag critical ต้องมี highlight ซ้ายมือของแถว          │
│  ...                                                          │
├─────────────────────────────────────────────────────────────┤
│  Pagination (ถ้าข้อมูลเกิน 1 หน้า)                             │
└─────────────────────────────────────────────────────────────┘
```

## Component ที่ใช้ประกอบ
- `lab-result-table.html` — ใช้ตรง ๆ ถ้าเป็นผลแล็บ หรือใช้เป็นต้นแบบโครงตารางสำหรับข้อมูลอื่น
- `status-badges.html` — คอลัมน์สถานะ/flag
- `form-controls.html` — search input, filter select

## กฎการใช้งาน
- Filter ที่เลือกอยู่ต้องแสดงผลทันที (client-side filter บน mock data ไม่ต้องรอ "โหลด" เว้นแต่จำลอง latency ตั้งใจ)
- คอลัมน์ตัวเลข/ค่าทางคลินิกใช้ `--font-family-mono` เพื่อให้ตัวเลขเรียงคอลัมน์ตรงกัน
- แถวที่มีค่า critical ต้องเด่นกว่าค่าอื่นในตาราง (ดูตัวอย่างใน `lab-result-table.html` — `.row--critical`)
- ถ้าผลลัพธ์ว่างเปล่า ต้องมี Empty state พร้อมข้อความแนะนำ (เช่น "ลองปรับเงื่อนไขการค้นหา")
