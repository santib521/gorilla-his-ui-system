# Gorilla HIS — Primary Workspace Render Gate v1.0

Status: `MANDATORY FACTORY GATE`

## Purpose
Stop the Factory from building an entire module on top of a weak composition.

Core:
`Contract → Build Primary Workspace Only → Render → Compare → Challenge → PASS or REDESIGN → then Full Build`

## 1. Trigger
Mandatory for every module with a material operational workspace.

In Benchmark Mode it is mandatory before secondary screens are materially built.
In Open Design Mode it remains mandatory against Visual DNA / Gold archetype evidence when available.

## 2. Primary Workspace Selection
Choose the workspace that best represents the module's most important recurring user job, not the easiest screen to implement.

Document:
- Work Obligation / `WL-*`
- `UXC-*`
- primary role
- why this is the module's primary operational surface
- controlling `KD-*` / `BM-*` constraints

## 3. Build Boundary
First build only enough to prove:
- shell/navigation relationship;
- first viewport hierarchy;
- dominant work surface;
- identity/context;
- state/owner/waiting condition;
- evidence hierarchy;
- attention/exception;
- Next Action;
- one representative state-changing interaction;
- component/control craft.

Do not hide a weak primary composition behind many secondary functions.

## 4. Mandatory Render
Render at the same target viewport as the controlling Human-approved benchmark when one exists.

Evidence required:
- primary workspace render;
- benchmark render or approved screenshot at comparable viewport;
- side-by-side review;
- `BM/KD → visible evidence` mapping.

Source inspection alone cannot PASS a visual rule when rendering is possible.

## 5. No-Regression Questions
Reviewer must explicitly answer:
1. Is the candidate's real work surface at least as dominant/useful?
2. Is workload/context easier or equally easy to grasp?
3. Is patient/case/work identity at least as clear?
4. Are state, waiting condition and Next Action at least as clear?
5. Is typography/control finish at least at the quality floor?
6. Is density useful rather than barren or noisy?
7. Does the composition feel purpose-built for this domain rather than generic?
8. Did any benchmark strength regress? If yes, is the regression materially justified by workflow/safety?

## 6. Result
Allowed results:
- `PASS — PRIMARY WORKSPACE RENDER GATE`
- `FAIL — BENCHMARK REGRESSION`
- `FAIL — GENERIC TEMPLATE`
- `FAIL — PROFESSIONAL WORKSPACE DEPTH`
- `FAIL — FIRST VIEWPORT COMPOSITION`
- `FAIL — COMPONENT/CRAFT QUALITY`

If FAIL:
`STOP → REDESIGN → RENDER AGAIN`.

Secondary/full module build is prohibited until PASS.

## 7. Independent Review Rule
The Builder cannot be the sole approver of this gate.

Independent challenger must use rendered evidence and the compiled contracts. Builder explanation is supporting context only.

## 8. Human Veto
Any Human statement that the controlling benchmark is visually/operationally better returns this gate to FAIL immediately.

## 9. Final Rule
**Do not spend Factory effort completing a weak product composition. Prove the primary workspace first.**
