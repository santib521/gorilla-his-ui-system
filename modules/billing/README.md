# Module: BILLING / CASHIER (การเงิน/แคชเชียร์)

เพิ่มเข้าระบบหลัง Visual Audit — ยืนยันว่าเป็น module จริงจากภาพหน้าจอ `22 bILLING.jpg` และ `23 Cashier worklist.jpg` ใน `../../screenshots/actual-gorilla-his/`

## บริบทธุรกิจ
รวบรวมค่าใช้จ่ายของผู้ป่วยจากทุก module (OPD/IPD/Lab/Pharmacy/OR ฯลฯ) เข้าเป็นบิลเดียว ตรวจสอบสิทธิ์การเบิก/ส่วนลด แล้วรับชำระเงินที่หน้าแคชเชียร์

## Flow หลักที่ต้องเข้าใจก่อนออกแบบ mockup
1. ระบบรวบรวมรายการค่าใช้จ่ายของผู้ป่วยจากทุก module อัตโนมัติ เข้าคิวใน **Billed WorkList**
2. เจ้าหน้าที่การเงินตรวจสอบรายการ — สิทธิ์การเบิก (ประกัน/สวัสดิการ/เงินสด), ส่วนลด, ยอดที่ผู้ป่วยต้องจ่ายจริง
3. ส่งบิลไปที่ **Cashier worklist** เพื่อรอรับชำระ
4. แคชเชียร์รับชำระเงิน (เงินสด/บัตร/โอน) ออกใบเสร็จ
5. ปิดบิล → อัปเดตสถานะกลับไปที่ module ต้นทาง (เช่น ปลดล็อกการรับยาเมื่อชำระแล้ว)

## ผู้ใช้งานหลัก
เจ้าหน้าที่การเงิน, แคชเชียร์, หัวหน้าฝ่ายการเงิน (สำหรับรายงาน/อนุมัติส่วนลดพิเศษ)

## สิ่งที่ต้องระวังเป็นพิเศษ
- ตัวเลขจำนวนเงิน (payor/amount/discount) ต้องจัดชิดขวาเสมอ ใช้ `--font-family-mono` ตามกฎใน `../../design-system/design-rules.md`
- ส่วนลดที่เกินเพดานปกติ (เช่น ส่วนลดพิเศษที่ต้องอนุมัติ) ต้องผ่าน pattern `approval-confirmation.md` ห้ามให้แก้ยอดได้อิสระโดยไม่มีการยืนยัน/บันทึกผู้อนุมัติ
- ห้ามใช้สีแดง/ส้ม/เหลือง (patient-safety semantic color) กับตัวเลขทางการเงินเพื่อสื่อ "ยอดสูง/ค้างชำระ" ปนกับความหมาย clinical — ถ้าจำเป็นต้องมีสีเตือนสำหรับสถานะบิล (เช่น ค้างชำระนาน) ให้ใช้ `--color-status-warning` ตามความหมายจริง (รอดำเนินการ) ไม่ใช่ critical
- บิลที่ปิดแล้ว (paid) ต้องแสดงเป็น read-only ชัดเจน แก้ไขย้อนหลังไม่ได้ในหน้าจอปกติ

## Pattern ที่มักใช้
- `search-and-table.md` — Billed WorkList / Cashier worklist

- `result-review.md` — ตรวจทานรายการก่อนปิดบิล
