# Module: PATIENT PORTAL (ช่องทางสำหรับผู้ป่วย)

## บริบทธุรกิจ
ช่องทางที่ผู้ป่วยเข้าถึงข้อมูลของตัวเองได้โดยตรง (เว็บ/แอป) แยกจากระบบที่เจ้าหน้าที่ใช้ในโรงพยาบาล

## Flow หลักที่ต้องเข้าใจก่อนออกแบบ mockup
1. ผู้ป่วย login ด้วยบัญชีตัวเอง
2. ดูประวัติการรักษา, ผล Lab, นัดหมายที่จะถึง
3. จองนัดหมายใหม่ / เลื่อน-ยกเลิกนัดด้วยตัวเอง
4. รับการแจ้งเตือน (แจ้งผลตรวจพร้อมดู, เตือนนัดหมาย)

## ผู้ใช้งานหลัก
ผู้ป่วย/ญาติผู้ป่วย (ไม่ใช่เจ้าหน้าที่โรงพยาบาล)

## สิ่งที่ต้องระวังเป็นพิเศษ
- **UI ต้องเรียบง่ายกว่า module อื่นมาก** — ผู้ใช้ไม่ใช่บุคลากรทางการแพทย์ ไม่คุ้นเคยกับศัพท์เทคนิค
- ต้อง responsive จริงจัง (มือถือเป็นหลัก) ต่างจาก module อื่นที่เน้น desktop 1366px (ข้อยกเว้นจาก `design-rules.md` § 2 — ระบุเหตุผลนี้ใน Design Notes)
- ผลตรวจที่มีค่าวิกฤต ไม่ควรแสดงให้ผู้ป่วยตกใจโดยไม่มีคำแนะนำให้ติดต่อแพทย์ประกอบ (เชื่อมโยงกับกฎ "clinical navigation ไม่ใช่การวินิจฉัย" ใน `AI_INSTRUCTIONS.md`)
